Pipeline · Contratos JSON

Contratos, nueva source of truth

Piensa en un contrato JSON como la ficha de una receta en la cocina: no es el plato (Figma), sino la etiqueta que dice exactamente qué ingrediente es cada componente, sus estados y tokens — para que dev no adivine.

Figma organizado→ Higiene→ Verify vs Android + JSON→ Contratos en draft→ Sello humano portero / Lead (~10–15 min)→ Eng consume solo lo sellado

En el PoC probamos…

  1. Probamos la verificación de gaps entre Figma, spec y código sin inventar.
  2. Probamos hacerlo de forma manual y automatizada.
  3. Mapeamos métricas de cada cosa.
  4. Al final: ¿sale un draft usable por el portero, que pueda calificarlo listo para handoff a ingeniería?

ANALOGÍA · Receta + etiqueta

  • Figma = plato presentado.
  • Contrato = etiqueta.
  • Sello = chef.

Cómo lo probamos

Mapa de pruebas 0→4 en feature real — automatización asistida + entrega sellada.

Método E2E en feature real
Figma organizado → higiene → verify vs Android + JSON → sello humano → eng consume solo lo sellado.

PruebaQué respondíaResultado
0 Baseline manual ¿Cuánto cuesta sin skills? Control: higiene/verify/contracts a mano (días, no horas)
1 Higiene usando skills ¿Claude Project + Figma MCP ordenan el canvas con OK humano? Sí: renombres/patrones asistidos; humano aprueba
2 Verify figma, specs y codigo usando skills ¿Detectamos gaps Figma↔spec↔código sin inventar? Sí: PASS/GAP honestos - Debe agregarse Claude Code + Figma Console MCP obligatoriamente
3 Contratos draft ¿Sale draft usable para portero? Sí, draft — no es el handoff eng
4 Manual Test PoC #2 ¿Podemos sellar happy path y entregar a eng? Sí: pack sealed · handoff (1 oct)

Lectura: pruebas 1–3 = automatización asistida; prueba 4 = entrega real.

Adopción · Diseño Applaudo

¿Y cuándo lo hacen los demás? Hay una curva técnica

Los tres caminos funcionaron — pero no cualquier diseñador puede repetirlos mañana sin apoyo.

Qué pide hoy

  • Acceso a repositorios y SDD, y saber manejarlos al menos a nivel fundamental
  • Leer y validar contratos JSON
  • Entender props de código
  • Prompts y agentes (Claude Project + Figma MCP)
  • Diseñar en código o en Pencil.dev
  • Saber cuándo un reporte se equivoca

La verdad

  • Estos caminos funcionaron porque los lideró alguien con conocimiento técnico
  • Un UI designer típico de Applaudo hoy no se atreve
  • La señal de tiempo del piloto no se traslada directo al equipo

Cómo ayudarles

  • Capacitación técnica especializada
  • Mini-curso por niveles
  • Campeones por squad
  • Shadowing
  • Plantillas y agentes que bajen la barrera
