Hallazgo principal

Si cambias la librería, los otros archivos no se enteran

MagicPath 0 de 3 archivos se actualizaron.

Paper El otro archivo no cambió ni un píxel.

Recomendación: una herramienta intermedia, como Storybook, entre diseño y código. Protege el código y da a los dos equipos una vista del código y sus librerías para revisarlas y mantenerlas.

Recomendaciones

Dónde usarlas, según el proyecto

Mejor encaje

Greenfield

Producto nuevo, desde cero, sin código ni sistema de diseño previos. Así fue Pulsar.

MagicPath: de la idea a pantallas en código, rápido; mejor si es interactivo y responsive.

Paper: explorar colores y tipografía, o pantallas fijas con pocos estados.

Buen encaje

Greyfield

Ya hay una base, de código o de sistema de diseño, y se suman flujos o un cambio de estilo.

MagicPath: trae los componentes que ya existen y suma flujos nuevos.

Paper: prueba rápidamente un cambio de estilo.

Encaje limitado

Brownfield

Producto maduro, con código y sistema de diseño establecidos. Así fueron Bain y Volaris.

Las dos: solo para explorar una funcionalidad aparte.

El riesgo: una segunda fuente de verdad que nadie mantiene.

Si eliges una sola: MagicPath, porque lo que entrega es código. En cualquier caso, las dos necesitan acompañamiento: agentes como Codex o Claude, y algo como Storybook para el sistema de diseño.

Recomendaciones
Herramientas de diseño con IA · Oct ’26
Informe Paper §11, «Use cases at Applaudo Studios, by project type» (recomendación, no resultado de prueba). Orden: greenfield (mejor) > greyfield (bueno) > brownfield (limitado). Pulsar es el caso greenfield (empezó sin sistema de diseño); Bain y Volaris partieron del código y el Figma de un sistema de diseño existente, por eso van como brownfield. Greenfield en Pulsar (informe Pulsar §9): producto interactivo y responsive, o entrega cercana al código → MagicPath; exploración visual estática con pocos estados → Paper; un sistema de diseño que va a crecer entre muchos archivos → ninguna: la fuente de verdad va fuera (código o Figma). El acompañamiento (agentes como Codex o Claude, y algo como Storybook) es recomendación de Adonay. Proyecto nuevo: MagicPath lleva de la idea a pantallas en código, con el código como fuente de verdad desde el día 1; Paper fija la dirección visual antes de fijar el sistema de diseño; riesgo: decidir pronto dónde vive el sistema oficial. Proyecto con base: MagicPath trae los componentes existentes y suma flujos nuevos; Paper carga los tokens actuales para probar cambios de estilo rápido («test reskins quickly»); riesgo: que se desincronicen. Producto maduro: solo exploraciones aisladas; riesgo: una segunda fuente de verdad que nadie mantiene, porque ninguna enlaza entre archivos. Si Applaudo elige una sola: MagicPath, porque lo que entrega es código (informe Paper §11). No usar para librerías compartidas entre equipos ni para gobernar el sistema de diseño.
